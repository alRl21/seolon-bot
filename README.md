# 설온지기

## v0.4 입장·역할·비용 설정

사용자가 명시 요청한 설정 번호 2026102703를 시작 시 한 번 적용합니다.
실패하면 무한 반복하지 않으며 `/입장설정`으로 원인을 확인하고 다시 적용할 수 있습니다.

- 기존 로그 채널 1523611752837681192의 ID·메시지는 유지하고 입장 공간의 `﹒입장로그`로 재사용합니다.
- `﹒역할받기`에는 공개 가입 신청 버튼을 둡니다. 버튼은 신청만 접수하며 역할을 직접 지급하지 않습니다.
- `클랜원`이 없으면 입장 공간만, 역할을 받으면 본 채널만 보이게 합니다.
- 나머지 보호 3개는 관리자 전용입니다. 이름·위치·메시지는 유지합니다.
- Discord 관리자 권한과 서버 소유자는 채널 숨김을 우회하므로 두 공간을 모두 볼 수 있습니다.
- 기본 입장 알림을 로그 채널로 연결하므로 회원 인텐트나 24시간 봇 가동이 필요하지 않습니다.
- 기존 회원에게 역할을 일괄 지급하지 않습니다. 소유자가 `/가입신청목록`, `/클랜원지급 대상`, `/클랜원회수 대상`을 사용합니다.
- 모든 슬래시 명령어는 계속 소유자 전용입니다. 공개 가입 신청 버튼만 회원에게 허용합니다.
- 설정 후 `/디자인`과 `/초기화`는 공개 채널 재생성으로 권한을 풀지 않도록 차단합니다.

운영 시간은 기존 07:00~24:00 KST를 유지합니다.
서비스 CPU 상한은 0.1 vCPU, 메모리 상한은 0.25GB입니다.
최근 1시간 관측을 이용한 비용 추정과 한계는 COSTS.md에 기록합니다.

## v0.3 소유자 승인 초기화

사용자가 보호 채널 4개 외 기존 대화 기록의 삭제에 동의했습니다.
보호 채널 중 문자 채널에서 `/초기화`를 실행하면 실제 삭제 목록 파일과 최종 확인 버튼을 보여줍니다.
소유자가 버튼을 눌렀을 때 새 디자인을 먼저 준비한 뒤, 확인한 기존 채널·카테고리 ID만 삭제합니다.
보호 채널과 그 상위 카테고리는 남깁니다. 회원·역할·출석·잔액은 유지합니다.
커뮤니티 규칙/업데이트 채널이 삭제 대상이면 새 채널로 연결 설정을 먼저 이전합니다.
채널 수 제한 등으로 새 채널 준비가 실패하면 삭제를 시작하지 않습니다.
삭제 도중 오류가 나면 부분 적용 상태를 보고하고 멈춥니다. 메시지·사진·파일은 복원되지 않습니다.
일반 `/디자인`은 계속 비파괴 방식으로 동작합니다.

## v0.2 디자인과 채널 보호

카테고리: `── ⟡ 처음의 설온 ⟡ ──`, `── ⟡ 머무는 공간 ⟡ ──`,
`── ⟡ 함께하는 순간 ⟡ ──`, `── ⟡ 쌓이는 발자국 ⟡ ──`, `── ⟡ 목소리의 온도 ⟡ ──`.
채널은 `﹒공지사항`, `﹒도란도란`과 같은 특수기호 형식입니다.

다음 채널 4개는 이름·소속 카테고리·권한을 유지합니다.
1523604140108939285 / 1523611752837681192 / 1523611037591535768 / 1522946795217490141.
보호 채널이 있는 카테고리는 이름을 바꾸지 않습니다.
기존 채널 중 새 구성에 맞는 것은 메시지를 유지한 채 재사용·이동합니다.
남는 공개 문자/음성 채널은 이전 기록 카테고리에 보관하고, 비공개 채널과 기타 채널 종류는 기존 위치에 둡니다.
이동 시 기존 권한 덮어쓰기를 명시적으로 유지하고 새 카테고리와 동기화하지 않습니다.
일반 /디자인 명령어에서는 채널·메시지·카테고리를 삭제하지 않습니다. 따라서 기존 빈 카테고리가 남을 수 있습니다.
전체 변경 목록은 `/디자인`의 첨부 파일에 표시되며 소유자가 적용 버튼을 눌러야 반영됩니다.
`＋ 새로운 방`은 일반 음성방이며 자동 생성 기능은 아직 없습니다.
명령어 보호, 출석, 예약 운영을 포함한 자동 검사 35개를 통과했습니다.

## 운영 시간

한국 시간 07:00~24:00에만 실행됩니다. Railway cron은 UTC 기준 `0 22 * * *`입니다.
자정에는 Discord 연결을 닫고 프로세스를 종료합니다. 00:00~07:00에 재배포되어도 봇은 접속하지 않습니다.
자동 재시작 정책은 NEVER로 설정해 자정 종료 후 다시 켜지지 않게 합니다.
오전 7시 시작은 Railway 예약 실행 특성상 수분 지연될 수 있습니다.
낮에 프로세스가 비정상 종료되면 다음 예약 실행까지 기다리거나 수동 재배포가 필요합니다.
새벽에도 저장 공간 및 요금제 기본 비용은 남을 수 있습니다.

설온 서버 전용 채널 디자인·출석 봇. 현재 온라인 실행 환경 연결 전입니다.

## 명령어

| 명령어 | 기능 |
| --- | --- |
| `/디자인` | 변경 내용을 미리 본 뒤 버튼으로 적용 |
| `/출석` | 한국 시간 기준 하루 1회 눈꽃 지급 |

모든 명령어와 적용 버튼은 코드에 지정된 소유자만 사용합니다.
다른 관리자도 실행할 수 없습니다. 출석 역시 현재는 소유자 테스트용입니다.
AI 대화·회원 제재·자동 음성방·상점 교환·역할 자동 지급은 아직 없습니다.

## 온라인 실행

Dockerfile과 railway.toml이 저장소 최상단에 포함되어 있습니다.
Railway에서 GitHub 저장소를 연결하고 다음을 설정합니다.

1. 서비스 Variables에 `DISCORD_TOKEN`을 추가하고 실제 봇 토큰을 값으로 입력합니다.
2. 영구 Volume을 서비스에 연결하고 Mount Path를 `/data`로 지정합니다.
3. 배포합니다. `DATA_DIR=/data`는 Dockerfile에 이미 설정되어 있습니다.
4. 로그에 `설온지기 연결 완료`가 표시되는지 확인합니다.
5. 설온 서버에서 지정된 소유자가 `/상태`, `/디자인` 순서로 확인합니다.

토큰은 GitHub 파일·이슈·커밋·ChatGPT 대화에 입력하지 않습니다.
현재 지정된 봇의 토큰인지 시작 시 확인합니다.
이 봇은 웹사이트가 아니므로 도메인 생성이나 HTTP 상태검사 경로는 필요하지 않습니다.
하나의 봇 프로세스만 실행하세요. 영구 저장 없이 재배포하면 잔액과 기록이 사라질 수 있습니다.
호스팅 요금과 무료 체험의 네트워크 제한은 서비스에서 확인해야 합니다.

## 디자인 범위

기존 카테고리와 채널의 알려진 이름을 찾아 이름을 변경하고, 없는 항목만 추가합니다.
후보가 중복되면 추측하지 않고 중단합니다. 기존 메시지와 채널을 삭제하지 않습니다.
기존 접근 권한과 기존 채널 순서는 유지합니다.
음성방도 새 디자인에 맞춰 재사용·생성합니다. 보호 채널과 비공개 공간은 유지합니다.
전체 서버 재정렬·자동 복원 기능은 없습니다.
